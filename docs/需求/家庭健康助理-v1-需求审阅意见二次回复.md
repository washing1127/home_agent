## 2. 关键决策要点固化

以下 10 项核心共识将作为新版需求编写的准则：

| 维度 | 最终共识决策 | 核心落地要求 |
| :--- | :--- | :--- |
| **产品原则** | **普通成员无感聊天** | 除管理员外，家庭成员无需配置账号、理解档案或事件类别，纯通过自然聊天完成记录、查询与纠错。 |
| **身份与鉴权** | **彻底取消普通成员 PIN** | 采用“管理员创建 -> 一次性邀请链接/二维码 -> 长期登录”。换机或失效由管理员重发邀请，手机丢失由管理员撤销设备。 |
| **管理与运维** | **取消 Web 后台，转为 CLI** | v1 不建管理员 Web 页面。由具备运维能力的管理员通过配置文件、Secrets、管理 CLI、日志及只读 SQL 维护；管理操作记录审计日志。 |
| **检索与 RAG** | **按需筛选，不做向量 RAG** | v1 明确不建向量库/Embedding。系统每轮根据问题从永久历史中按需筛选相关事实，禁止把全量家庭历史无脑拼入 Context。 |
| **多 LLM 范围** | **收敛为未来扩展，v1 单模型** | v1 仅实现单一 LLM 调用与用量/费用记账，支持 Provider 可替换与解耦；多模型审查/裁判等编排全量延后至 v2。 |
| **公开网页读取** | **收窄范围，严控安全** | 仅支持用户主动提供的公开 HTTP/HTTPS 静态正文提取；严禁内网访问（防 SSRF）；获取失败降级提示用户截图/复制；超时与大小可配置。 |
| **关键数据闭环** | **聊天内轻量确认，不做独立模块** | 药名、剂量、过敏、体检数值等关键信息依托聊天内轻量提示卡片确认（可点击操作或直接语音/文字纠正），未确认不作为正式健康事实。 |
| **提醒推送降级** | **PWA 通知 + 应用内双重唤起** | Web Push 作为系统通知；同时在 PWA 首屏常驻今日待办，且用户当日首轮发起对话时，Agent 可顺带提示到期/待办事项。 |
| **多模态与长文件** | **弹性约束与阶段反馈** | 医嘱长录音与多页 PDF 体检报告必须有可配置的上限；长任务必须在界面呈现分段/阶段状态流，且失败绝不丢失已上传的原始文件。 |
| **上下文与备份** | **256k 弹性预算 + 外部异机备份** | 上下文默认预算暂定 256k 且可配置；异机备份必须离开当前服务器、加密并支持 S3 兼容存储/NAS/WebDAV 等外部介质，完成恢复演练。 |

## 3. 下一版 PRD 撰写对照指南（供修改参考）

为便于你顺畅输出下一版《家庭健康助理-v1-产品需求.md》，以下梳理了需要联动调整的章节及修改建议：

### 3.1 明确删除的内容
- **删除关于普通成员 PIN 码的所有描述**：
  - 第 8.1 节中“使用简单 PIN 作为换设备或登录失效时的兜底”；
  - 第 19 节隐私要求中的“PIN 不得明文保存”；
  - 第 23.1 节清单中的“PIN”；
  - 第 25 节验收场景中涉及 PIN 验证的条目。
- **删除关于管理员 Web 后台的所有描述**：
  - 第 5.1 节与第 16.2 节中的“管理员端界面/后台”；
  - 第 23.1 节清单中的“最小管理员后台”；
  - 第 25 节验收场景中关于 Web 后台操作的条目。

### 3.2 重点改写与增补的章节
- **第 4 节（非目标）**：
  - 修正天气口径：删除原有的“天气与症状关联”非目标，明确改为“每日自动天气简报”与“未经请求的主动环境建议”属于非目标；
  - 明确“向量知识库与 Embedding 流水线”、“多 LLM 协作编排”属于非目标。
- **第 6 节（家庭信息原则） / 第 2 节（产品定位）**：
  - 增补全局原则：“**普通成员无感聊天原则**——除管理员外，家庭成员完成日常记录、查询、提醒和纠错时，应尽量只需自然聊天；除邀请登录和系统权限授权外，不要求其配置账号、维护档案或进入专门管理页面。”
- **第 7.5 节（多维检索与分析） / 第 14.1 节（查询原则）**：
  - 写入明确约束：“系统面对用户问题时，必须根据当前问题选择相关历史，不要求使用向量检索，也不得默认把全部家庭历史直接发送给模型。”
- **第 8.1 节（创建与邀请）**：
  - 改写为完整的极简邀请与运维闭环：“管理员创建成员 -> 下发一次性邀请链接或二维码 -> 设备长期保持登录；换机或失效由管理员重新下发邀请；设备丢失由管理员后台撤销该设备登录态。”
- **第 9.1 & 9.3 节（多模态输入与理解）**：
  - 网页读取收窄：明确仅支持公开静态正文提取，禁止内网 IP 访问，超时与体积可配置，失败降级提示复制或截图；
  - 输入规格：明确音频时长、图片大小、PDF 页数等必须具备可配置上限，大文件长任务必须呈现阶段处理状态，失败不丢原件。
- **第 11.2 & 11.3 节（记忆交互与状态）**：
  - 明确“双通道操作”：Agent 在对话中展示轻量提示与操作项，同时原生支持自然语言快速撤回/修改（如“刚才那条别记了”），操作后给出明确反馈；
  - 明确关键数据（药名、剂量、过敏、体检异常值）依托轻量确认卡片完成闭环，未确认不作为正式健康事实。
- **第 15.3 节（提醒送达与降级）**：
  - 补充应用内兜底：PWA 首屏常驻“今日待办”，且用户当日首次打开对话时，Agent 可顺带跟进主动创建但即将到期的提醒。
- **第 16 节（客户端需求）**：
  - 彻底精简为纯粹的“成员移动端 PWA 界面”，专注聊天流与轻量交互；
  - 将管理员运维能力明确移至系统管理规范（配置、Secrets、管理 CLI、日志）。
- **第 17.3 节（数据备份）**：
  - 明确异机目标类别：支持将加密备份快照自动同步至管理员提供的 S3 兼容对象存储、NAS 或 WebDAV。
- **第 21 节 & 第 22 节（技术约束与模型管理）**：
  - 管理方式升级为：版本化配置 + 环境变量/Secrets + 管理 CLI；要求管理 CLI 的修改操作保留结构化审计日志；
  - 第 22 节重点精简为“LLM Provider 抽象与调用度量要求”：记录模型、耗时、Token、费用与错误，实现业务与模型解耦；将生成加审查、并行专家、多方案裁判等复杂编排明确划入 v2 路线图。
- **第 23 节（功能清单）**：
  - 必须实现清单：加入“管理 CLI 运维系统”、“256k 可配置上下文预算”、“提醒应用内双重唤起”、“公网网页正文只读”；移出“Web 后台”与“PIN”。
- **第 25 节（验收场景）**：
  - 同步对照更新：将第 2 条（PIN 换机）、第 10 条（Web 后台查看）等更新为“管理员通过 CLI 撤销设备并生成新邀请码恢复登录”、“管理员通过 CLI 查看审计与调用量”、“长任务阶段状态显示与失败原件不丢”等新验收标准。
